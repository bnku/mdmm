# Задача 01. Include целых диаграмм

**Статус:** ✅ Реализован прототип

## Цель

Ввести минимальный и понятный механизм переиспользования Mermaid-диаграмм между Markdown-документами без изменения привычного authoring flow для аналитиков и бизнес-команды.

Задача должна снять основную боль от копипасты: общая диаграмма или канонический подпроцесс описывается один раз и затем вставляется в любые документы через include, а не копируется вручную.

## Источники требований

- `../00-roadmap.md`
- `../../01-intro-and-architecture.md`
- Пользовательский запрос в текущей planning-сессии: сохранить документацию в `Markdown + Mermaid`, допустить встраивание диаграмм в произвольные `.md`-документы.

## Что входит в задачу

- Определить v1-спецификацию синтаксиса `mermaid-include` для вставки целой диаграммы.
- Определить синтаксис объявления канонического Mermaid-блока внутри обычного `.md`.
- Реализовать препроцессор, который разворачивает include в итоговый Markdown.
- Добавить базовую валидацию include-ссылок и блоков.
- Встроить шаг сборки в существующий documentation pipeline или оформить отдельную CLI-утилиту.
- Подготовить авторскую документацию: как создавать канонический блок, как вставлять его в другие документы, какие ограничения действуют.

## Что НЕ делаем в этой задаче

- Не реализуем вставку Mermaid-фрагментов внутрь другой Mermaid-диаграммы.
- Не внедряем alias/prefix rewriting для node id.
- Не строим отдельный DSL, source model или JSON/YAML-слой поверх документации.
- Не делаем автогенерацию usage-map, dependency graph или редакторскую UI-надстройку.
- Не поддерживаем include по диапазонам строк.

## Основные задачи по слоям

### Feature

- Зафиксировать формат канонического блока через `<!-- mermaid:block <block-id> --> ... <!-- /mermaid:block -->`.
- Зафиксировать формат вставки через fenced-блок ` ```mermaid-include ` с путем и `block id`.
- Реализовать поиск блоков в `.md`-файлах и разворачивание include в обычный ` ```mermaid `.
- Определить правила разрешения относительных путей и обработки файлов в разных директориях документации.
- Определить библиотечную структуру для общих диаграмм, не привязывая ее жестко к конкретному SSG.
- Обеспечить, чтобы итоговый build output не содержал кастомный синтаксис и оставался обычным Markdown.

### Backend

- Отдельный backend не требуется.
- Если документация собирается серверным пайплайном, определить точку вызова препроцессора до финального Markdown-рендеринга.

### Frontend

- UI продукта не затрагивается.
- Если используется docs frontend, убедиться, что после разворачивания include рендеринг Mermaid остается штатным и не требует кастомного клиентского компонента.

### Contracts/API

- Описать формальную спецификацию `block id` и include-синтаксиса.
- Зафиксировать список ошибок препроцессора: missing file, missing block, duplicate block id, cyclic include, unresolved directive.
- Описать, какие конструкции считаются валидными, а какие отклоняются на этапе сборки.

### Tests

- Покрыть парсинг позитивными кейсами: один include, несколько include, относительные пути, несколько блоков в одном файле.
- Покрыть негативные кейсы: несуществующий файл, несуществующий блок, дублирующийся block id, циклический include.
- Добавить smoke-тест на сборку итогового Markdown и успешную Mermaid-валидацию через `mermaid-cli`.
- Проверить, что после сборки не остаются неразрешенные `mermaid-include` блоки.

### Docs

- Описать правила авторинга канонических диаграмм.
- Описать соглашение по именованию `block id`.
- Добавить примеры `до/после` для авторов документации.
- Зафиксировать ограничения первой версии и явный переход ко второму этапу только при реальной необходимости.

## Критерии готовности

- Каноническая Mermaid-диаграмма может быть объявлена в одном `.md` и безопасно вставлена в другой `.md` через include.
- После сборки итоговый документ содержит обычный ` ```mermaid ` блок, а не кастомную директиву.
- Основные ошибки include обнаруживаются до публикации документации.
- В pipeline есть автоматическая Mermaid-валидация.
- Для авторов есть короткая и понятная инструкция по использованию механизма.
