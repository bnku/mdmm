# Задача 03. CLI surface, init и базовый onboarding

**Статус:** ✅ Реализован прототип

## Цель

Сделать первый контакт с `mdmm` понятным без изучения исходников и внутренних npm-скриптов.

После выполнения этой задачи пользователь должен понимать, как запустить CLI через `npx`, как установить его глобально, как инициализировать новый docs-проект и какие команды составляют устойчивый публичный surface инструмента.

## Источники требований

- `../00-roadmap.md`
- `../../README.md`
- `../../src/cli.js`
- `../../package.json`
- Пользовательский запрос в текущей DX-сессии: нужен install/init flow, понятные варианты запуска и подготовка surface для будущего `adopt`.

## Что входит в задачу

- Перевести CLI с простого `if/else`-ветвления на явный command registry или эквивалентный слой, куда можно безопасно добавлять новые команды.
- Добавить `mdmm init` для greenfield-сценария.
- Добавить `mdmm --version`.
- Зафиксировать поведение `mdmm` без аргументов: help + next steps, а не скрытый запуск `check` или `init`.
- Зарезервировать имя команды `mdmm adopt` и дать пользователю понятный placeholder-ответ, не выполняющий мутаций.
- Поддержать non-interactive mode для `init`, чтобы команду можно было покрыть тестами и использовать в автоматизации.

## Что НЕ делаем в этой задаче

- Не реализуем реальное внедрение `mdmm` в существующий docs-проект; это отдельный будущий поток под `adopt`.
- Не добавляем автоизменение `.gitignore`, CI-конфигурации или package manager scripts в чужом проекте.
- Не добавляем rich TUI, мастера на несколько экранов, спиннеры или визуальные меню.
- Не реализуем эвристический анализ повторяющихся диаграмм.

## Основные задачи по слоям

### Feature

- Реализовать единый реестр команд CLI с описанием имени, алиасов, аргументов и обработчика.
- Добавить команду `init`, которая интерактивно спрашивает `docsDir`, `sharedDir`, `outputDir`, предлагает создать starter-файлы и создает минимально работоспособную структуру проекта.
- Добавить флаги `--yes`, `--force` и `--no-starter` для `init`.
- Обновить help так, чтобы он показывал quickstart для пустой директории и различал greenfield path (`init`) и future retrofit path (`adopt`).
- Добавить placeholder-команду `adopt`, которая явно сообщает, что сценарий planned, и не меняет файлы.

### Backend

- Отдельный backend не требуется.
- Если в будущем `mdmm` будет вызываться из server-side docs pipeline, command registry и scaffold-слой должны быть переиспользуемыми без зависимости от интерактивного режима.

### Frontend

- UI продукта не затрагивается.
- CLI остается текстовым интерфейсом без браузерной или desktop-обвязки.

### Contracts/API

- Зафиксировать публичный surface: `mdmm`, `mdmm --help`, `mdmm --version`, `mdmm init`, `mdmm build`, `mdmm check`, `mdmm report`, `mdmm adopt`.
- Зафиксировать поведение `mdmm init` при коллизии файлов: без `--force` команда ничего не перезаписывает.
- Зафиксировать минимальный scaffold: `mdmm.config.json`, каталоги `docs/`, `shared/`, `dist/`, starter docs при отсутствии `--no-starter`.
- Зафиксировать, что `adopt` в placeholder-версии возвращает явное сообщение о planned flow и завершается без изменения проекта.

### Tests

- Добавить тесты на `mdmm` без аргументов: help содержит next steps и ссылки на `init`.
- Добавить тесты на `--version`.
- Добавить тесты на `init --yes` и `init --yes --no-starter`.
- Добавить тесты на защиту от перезаписи существующего `mdmm.config.json` и starter-файлов без `--force`.
- Добавить тест на `adopt` placeholder: понятный текст, код завершения успеха или контролируемый non-error статус без мутаций.

### Docs

- Обновить README вокруг первых трех минут использования: `npx mdmm`, `npx mdmm init`, `mdmm build`, `mdmm check`.
- Добавить примеры для глобальной установки и локальной установки как devDependency.
- Явно описать разницу между `init` и будущим `adopt`.

## Критерии готовности

- Пользователь может запустить `mdmm` в пустой директории и сразу понять следующий шаг.
- `mdmm init --yes` создает минимальный рабочий проект без ручного редактирования конфига.
- Новый command surface расширяем и не заставляет переписывать весь `src/cli.js` при добавлении `adopt` или других команд.
- В help и README нет скрытой зависимости от внутренних repo-скриптов.

- Добавлены CLI-тесты на help, version, `init --yes`, `init --yes --no-starter`, защиту от перезаписи без `--force` и placeholder `adopt`.
- `../../README.md` обновлен под сценарии `npx`, global install и devDependency.
