# Roadmap: Синхронизация Mermaid include для Markdown-документации

## Назначение документа

Этот roadmap фиксирует согласованную последовательность внедрения синхронизации и переиспользования Mermaid-диаграмм в Markdown-документации без отказа от привычного authoring-подхода.

Документ является главным индексом feature-пакета `mermaid-include-sync`.

## Источники требований

- Пользовательский запрос в текущей planning-сессии: сохранить `Markdown + Mermaid`, убрать копипасту и снизить риск неконсистентности.
- Исследование по архитектурным паттернам синхронизации Mermaid в экосистеме Markdown, предоставленное пользователем в текущей planning-сессии.
- `./01-intro-and-architecture.md`

## Зафиксированные решения

- Основной путь внедрения: `MD-first preprocessor`, а не `DSL`, `JSON/YAML source model` или жесткая привязка к конкретному SSG.
- Канонические диаграммы и переиспользуемые фрагменты должны храниться в обычных `.md`-файлах, чтобы аналитики и бизнес продолжали работать в привычном формате.
- В первую очередь внедряется `include` целой диаграммы, потому что это самый простой и устойчивый способ снять основную боль от копипасты.
- Второй этап добавляет `include` фрагмента внутрь `mermaid`-блока только после стабилизации первого этапа.
- Синтаксис должен быть читаемым в исходном Markdown и не должен требовать от авторов знания внутреннего пайплайна сборки.
- Проверки консистентности и синтаксическая валидация Mermaid должны выполняться в CI.

## Границы работ

### Что входит в первую очередь

- Спецификация минимального синтаксиса include для целых диаграмм.
- Препроцессор, который разворачивает include-блоки в обычный Markdown с Mermaid.
- Поддержка канонических блоков в `.md`-файлах с явными block id.
- Базовые проверки: путь, block id, циклы include, остаточные неразрешенные директивы.
- Валидация итоговых Mermaid-диаграмм через `mermaid-cli`.
- Документация для авторов и правило работы с общей библиотекой диаграмм.

### Что переносится дальше

- Композиция нескольких переиспользуемых фрагментов внутри одной диаграммы.
- Alias/prefix rewriting для безопасной вставки фрагментов.
- Экспортируемые узлы (`exports`) и правила ссылок на них.
- Расширенные проверки конфликтов node id и ошибок связывания после раскрытия include.
- Генерация индекса usage-map или отчетов по неиспользуемым блокам.

## Общие правила для всех task-документов

- Следовать схеме `feature -> tests -> docs`.
- Не вводить отдельный DSL или новую модель данных, пока задачу можно решить на уровне Markdown-препроцессинга.
- Не использовать include по диапазонам строк; только именованные блоки.
- Не разрешать неограниченную глубину вложенных include на первом проходе.
- Любые изменения синтаксиса должны сопровождаться примерами, негативными кейсами и правилами миграции документации.
- Любой build output должен проходить автоматическую Mermaid-валидацию до публикации.

## Порядок задач

### Задача 01. Include целых диаграмм

**Статус:** ✅ Реализован прототип

Цель: убрать массовую копипасту одинаковых диаграмм между Markdown-документами и ввести канонические Mermaid-блоки с безопасным и понятным include-синтаксисом.

Текущий результат: в `../../src/` реализован standalone CLI-препроцессор с командами `build` и `check`, добавлены примеры, unit-тесты и отдельный скрипт Mermaid-валидации через `mermaid-cli`.

Подробности: `./todo/01-whole-diagram-includes.md`

### Задача 02. Include фрагментов внутри Mermaid

**Статус:** ✅ Реализован прототип

Цель: добавить композицию больших диаграмм из переиспользуемых Mermaid-фрагментов без конфликтов node id и без ручной склейки текста авторами документации.

Текущий результат: в `../../src/` добавлена поддержка `type=fragment`, inline-директив `%% include: ... as ...`, alias-префиксации `<alias>__<node-id>`, проверки `exports`, примеры и автоматические тесты.

Подробности: `./todo/02-fragment-includes.md`

## Ожидаемый итог

После завершения feature-пакета проект должен иметь:

- минимальный, понятный и документированный include-синтаксис поверх обычного `Markdown + Mermaid`;
- каноническую библиотеку переиспользуемых Mermaid-блоков в `.md`-файлах;
- сборочный шаг и CI-проверки, которые не дают опубликовать несинхронизированные или синтаксически невалидные диаграммы;
- поддержку двух уровней переиспользования: целой диаграммы и Mermaid-фрагмента.
